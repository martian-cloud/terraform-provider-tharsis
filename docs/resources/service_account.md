# tharsis_service_account (Resource)

Defines and manages a service account.

## Example Usage

```terraform
resource "tharsis_service_account" "this" {
  name        = "my-service-account"
  description = "A service account for CI."
  group_id    = tharsis_group.top_level.id

  oidc_trust_policies = [
    {
      issuer = "https://gitlab.com"
      bound_claims = {
        "sub" = "project_path:my-org/my-project:ref_type:branch:ref:main"
      }
    }
  ]
}
```

## Behavior

- Service accounts are used for machine-to-machine authentication, such as from CI/CD pipelines.
- A service account is created within a group.
- It authenticates through OIDC trust policies. Each policy specifies an `issuer` URL (for example `https://gitlab.com`) and `bound_claims`, which are checked against the token issued by the identity provider.
- A service account has no access until it is added as a member of a group or workspace with a role. Memberships are not managed by this provider. The `deployer` role is generally sufficient.

## Permissions

Editing a service account that has memberships requires the owner role in every group and workspace where it is a member.

## Import

Import is supported using the following syntax:

In Terraform v1.5.0 and later, the [`import` block](https://developer.hashicorp.com/terraform/language/import) can be used with the `id` attribute, for example:

```terraform
# A service account can be imported by its TRN, which is "trn:service_account:"
# followed by the group path and the service account name.
import {
  to = tharsis_service_account.this
  id = "trn:service_account:my-group/my-service-account"
}

# The service account's ID also works as the id, shown by the "id" attribute or
# in the Tharsis UI.
```
