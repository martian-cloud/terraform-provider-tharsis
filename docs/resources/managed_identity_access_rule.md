# tharsis_managed_identity_access_rule (Resource)

Defines and manages a managed identity access rule.

## Example Usage

```terraform
resource "tharsis_managed_identity_access_rule" "eligible_principals" {
  managed_identity_id         = tharsis_managed_identity.aws.id
  type                        = "eligible_principals"
  run_stage                   = "plan"
  allowed_service_account_ids = [tharsis_service_account.this.id]
}

resource "tharsis_managed_identity_access_rule" "module_attestation" {
  managed_identity_id  = tharsis_managed_identity.aws.id
  type                 = "module_attestation"
  run_stage            = "apply"
  verify_state_lineage = true

  module_attestation_policies = [
    {
      public_key     = file("${path.module}/attestation-key.pem")
      predicate_type = "https://slsa.dev/provenance/v1"
    }
  ]
}
```

## Behavior

- By default, anyone with deployer access to a managed identity can assume it. Access rules restrict this.
- Rules of the same type are combined with OR logic: one match is enough. Rules of different types are combined with AND logic: at least one rule of each type must match.
- A rule applies to one run stage, `plan` or `apply`. If no rule exists for a stage, any principal may assume the identity for that stage.

## Rule types

- `eligible_principals` limits use to specific users, teams, or service accounts, given by `allowed_user_ids`, `allowed_team_ids`, and `allowed_service_account_ids`.
- `module_attestation` requires the root module to carry an attestation signed with the public key of one of the `module_attestation_policies`. This is supported only for modules in the Tharsis registry.

## State lineage

When `verify_state_lineage` is true, the rule also verifies that the workspace's current state came from the same module source. It defaults to false.

## Import

Import is supported using the following syntax:

The [`terraform import` command](https://developer.hashicorp.com/terraform/cli/commands/import) can be used, for example:

```shell
# An access rule has no human-readable name, so import it by its ID, shown by
# the "id" attribute or in the Tharsis UI.
terraform import tharsis_managed_identity_access_rule.eligible_principals <access-rule-id>

# A TRN works too, but its last segment is the same rule ID, so it offers no
# advantage over using the ID on its own.
terraform import tharsis_managed_identity_access_rule.eligible_principals trn:managed_identity_access_rule:my-group/my-aws-identity/<access-rule-id>
```
